  - npm workspaces (`packages/*`, `templates/*`, `games/*`, `tools/*`), Node ≥22.12, strict TS via `tsconfig.base.json`.
  - Pinned dev dependencies: TypeScript 6.0.3 (TS 7 isn't supported by typescript-eslint yet), Vite 8.3.1, Vitest 5.0.2, ESLint 10 + typescript-eslint 8.71, Prettier 3.9.

  - Root scripts: `dev` (prints usage), `build`, `typecheck`, `lint`, `format(:check)`, `test`, `size`, `check`, `e2e`, `new-game` (stub until M4).

  - `.github/workflows/ci.yml`: `npm ci` → `playwright install --with-deps chromium` → `check` → `e2e`, and it uploads the report on failure.
- **M1 packages**
  - `@feedplay/engine` covers the fixed-step loop (with `timeScale`), scene stack, unified input, and seeded RNG (xmur3 → mulberry32, with `fork`). It also has tweens with easings (instant under reduced motion), WebAudio blips/noise with mute, strings, and canvas helpers.
    - All DOM access is in `src/dom.ts`: DPR-aware 9:16 fit, resize, pointer/key wiring, rAF, visibility, AudioContext, media query.
    - An ESLint rule enforces this for the rest of the engine.
  - `@feedplay/platform`
    - The `PlatformAdapter` interface has `init`, `setLoadingProgress`, `start`, `getSeed`, `getChallenge`, `submitScore`, `share`, `storage`, and `on('pause'|'resume')`.
    - The `web` adapter reads challenge links `?c=<seed>&s=<score>`, uses native share with a clipboard fallback, and falls back to memory storage when storage is blocked.
    - The `mock` adapter records every call.
    - `runAdapterContract()` (exported as `@feedplay/platform/contract`) runs against both adapters. Later adapters must pass it.
  - `@feedplay/analytics`: typed `EventMap` for the 7 CLAUDE.md events, `createAnalytics`, and console and memory sinks.
- **M2 template and game #1**
  - `@feedplay/template-score-attack`
    - A DOM-free `ScoreAttackController` (idle → play → end) with:
      - the round timer and instant restart on the same seed
      - share and challenge through the adapter
      - mute and reduced-motion toggles, persisted through adapter storage
      - all analytics and `submitScore`.
    - `hud.ts` draws the timer, score, multiplier, "Beat N", toggles, end card and toast.
    - `boot.ts` wires in the engine and handles the URL flags `?adapter=mock|web`, `?test=1` (`window.__feedplay` hook), `?autoplay=1` and `?speed=N`.
  - **`games/tidewall`** (concept seed 1)
    - You hold to raise the lit seawall segment and release on the dashed crest line.
      - A Perfect gives the multiplier +1 (cap ×8).
      - Too high scores less and resets the multiplier.
      - Too low is a breach.
    - Rounds last 45 s, and the waves speed up.
    - Deterministic sim, autoplay bot, and a colorblind-safe palette with a shape for every grade.
    - All text is in `strings.json` and all tunables are in `game.config.json`.
    - `SPEC.md`, `HORIZON_PACK.md` and `RELEASE.md` are written.
    - **Bundle: 11.0 KB gzipped** out of the 300 KB budget.

## How to run game #1 locally
```bash

npm ci
npm run dev -w games/tidewall            # http://localhost:5173 (and your LAN IP for a phone)
# handy flags: /?autoplay=1&speed=4   /?adapter=mock&test=1   challenge: /?c=my-seed&s=1200

```
